 Sistema Multiplataforma del Perfil Estudiantil - Ingenieria en Sistemas

Este archivo contiene 3 ejemplos VALIDOS para cada campo de cada entrada del
sistema, agrupados en 3 FLUJOS segun el rol que ejecuta la accion:

   FLUJO 1 - ESTUDIANTE        (registro, perfil, intereses, habilidades,
                                proyectos, certificados, inscripciones)
   FLUJO 2 - DOCENTE           (actividades, confirmacion de asistencia,
                                constancias internas)
   FLUJO 3 - DIRECTOR / ADMIN  (alta de usuarios, catalogos)

Todos los ejemplos respetan las reglas de validacion vigentes:
   - Sin espacios al inicio/fin (se recortan) ni dobles espacios internos.
   - Sin caracteres invisibles ni de control (se eliminan).
   - Acentos y la enie SI estan permitidos en nombres y textos.
   - Correo SIEMPRE institucional (termina en univalle.edu).
   - Contrasena: mayuscula + minuscula + numero + simbolo, sin espacios, 8-72.
   - Rangos: semestre 1-8 | prioridad de interes 1-5 | nivel de habilidad 1-5.
   - Sin duplicados en arreglos (intereses, habilidades, tecnologias, tags).
   - Fechas de emision de certificado NO pueden ser futuras.

Convencion de cada bloque:  CAMPO  ->  tipo / regla
                            1) ejemplo
                            2) ejemplo
                            3) ejemplo

 ANEXO - EJEMPLOS QUE EL SISTEMA RECHAZA (PARA PROBAR LAS VALIDACIONES)
================================================================================

NOMBRE invalido:
   "Ana123"            -> tiene numeros
   "  "                -> vacio tras recortar
   "Jose@Maria"        -> simbolo no permitido

CORREO invalido:
   "ana@gmail.com"             -> no es institucional
   "ana.perez@univalle.com"    -> no termina en univalle.edu
   "ana perez@univalle.edu"    -> tiene espacio

CONTRASENA invalida:
   "clave123"          -> sin mayuscula ni simbolo
   "Clave 123*"        -> contiene espacio
   "Ab1*"              -> menos de 8 caracteres

SEMESTRE invalido:   0 (menor a 1) | 9 (mayor a 8) | "tres" (no numerico)
PRIORIDAD / NIVEL invalido:   0 | 6 | 3.5 (debe ser entero 1-5)

ARREGLOS con duplicados (se rechazan o se deduplican):
   intereses con la misma area dos veces        -> 400 area duplicada
   technologies: ["React","react","REACT"]      -> se guarda solo ["React"]

FECHA de certificado futura:
   "2030-01-01"        -> 400 la fecha de emision no puede ser futura

CARACTERES RAROS (se limpian automaticamente):
   "  Ana   Maria  "        -> "Ana Maria"     (recorta y colapsa espacios)
   "Hola<caracter invisible>Mundo" -> "HolaMundo"  (elimina invisibles/zero-width)
